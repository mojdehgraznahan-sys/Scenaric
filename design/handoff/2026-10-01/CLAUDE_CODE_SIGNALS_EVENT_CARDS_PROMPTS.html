Prompt D — Port the card components

Port these components from components/events.jsx into the production codebase, matching the repo's file and styling conventions. Keep the visual output identical to the prototype.

1. FlipCard({ id, flipped, front, back, focused })
   - Both faces share a single CSS grid cell (grid-area: 1/1) so the card height = the taller face. Do not use absolute positioning.
   - rotateY(180deg) with perspective 1200px, 0.45s cubic-bezier(.2,.7,.2,1), backface-visibility hidden on both faces.
   - CRITICAL: set pointer-events: none on the hidden face, and aria-hidden on it. Without this, clicks on a flipped card hit buttons on the back of the hidden face. This was a real bug in the prototype.
   - Honour prefers-reduced-motion: swap instantly with no rotation.
   - `focused` renders a 2px #F97316 ring with a soft outer halo, used after a cross-view jump.
   - Put data-card-id={id} on the root for scroll targeting.

2. EventCard: front face must match the signal card exactly (same border #E5E7EB, radius 10, padding 14, fonts, sizes):
   - Row 1: colour-coded STEEP chip (className chip chip-<category>) on the left. On the right, mono 10.5px "<STATUS> · <date>" in #9CA3AF, or #7C3AED for wildcards.
   - Title 14px/600, description 12.5px #6B7280.
   - Wildcards only: "EARLY SIGN <precursor>".
   - IMPACT row: mono label (fixed 78px width) + Stars. Observed events show their source right-aligned on this row.
   - LIKELIHOOD row, ALWAYS shown:
     - possible/wildcard: a 3-segment bar (orange for filled segments) plus a badge-high/mid/low pill reading High / Medium / Low, or "Not set".
     - observed: a neutral "Occurred" pill. Likelihood never applies once something has happened.
   - Footer divider: "N linked force(s)", an INDICATOR tag if an indicator references the event, and a "FORCES ↻" flip hint.
   Back face: "LINKED FORCES", then each linked signal as a button showing its STEEP chip, title, and "pushes toward <pole> →". Clicking one jumps to that signal in the Forces view.

3. SignalCardBack: "LINKED EVENTS", the signal title, then its events (observed first, then possible), each as a button with:
   - title
   - date (observed) or likelihood pill (possible)
   - "→ <pole>"
   - a solid border for observed events, dashed for possible (orange #FDBA74), dashed purple (#C4B5FD) for wildcards

   Clicking an event jumps to it in the Events view. Footer: a "Timeline & details" button that opens the existing signal detail modal, plus a "FORCE ↻" hint.

4. EventCount: "● N evidence" (solid dot) and "◌ N ahead" (dashed dot), shown on the signal card front footer next to an "EVENTS ↻" flip hint.

Every inner button inside a face must stopPropagation so it doesn't also flip the card.

Prompt F — Verify

Verify without changing behaviour. Fix only what's broken, and report results.

1. Hidden-face clicks: flip a signal card, then click where "+ Add to Matrix" sits on the front. Assert no navigation happens. Repeat for event cards.
2. Card height: a card with a long back face (a signal with 5+ events) grows to fit. Nothing is clipped or overlaps the next row.
3. Likelihood: every possible and wildcard card shows the LIKELIHOOD row with a bar and a pill. Every observed card shows "Occurred". No observed card shows High/Medium/Low.
4. STEEP chips: every event card shows a coloured category chip, including events whose category column is null (fallback to the linked signal).
5. Jumps: signal back → event lands in the Events view with the card highlighted and scrolled into position, even when a STEEP filter was active that would have hidden it. Same for event back → signal.
6. Filters: the STEEP filter applies in both views, and the status filter only appears in Events.
7. Realtime: accept a news-match proposal in another tab, then assert the event card moves from Possible to Observed and its likelihood row changes to "Occurred", with no reload.
8. Reduced motion: with prefers-reduced-motion, flips are instant.
9. Keyboard: cards are focusable. Enter or Space flips a card. Inner buttons are reachable only on the visible face.
10. Heuristic: "US adds 14 firms to Entity List" and "Tariff hike in Q3 2027" trigger the event nudge. "Direction of SEA foreign-ownership regulation" does not.

Hold the implementer to

  • The prototype is the spec. Card anatomy, colours and copy come from components/events.jsx and components/page-signals.jsx. Don't reinterpret them.
  • Hidden faces must not be clickable. It's the one non-obvious bug in a flip UI, and it silently triggers the wrong action.
  • Likelihood is per event only. It shows on event cards and nowhere on scenarios.
